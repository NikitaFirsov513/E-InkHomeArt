# Техническое задание — E-Ink Home Art

**Версия:** Revision 1 (проектное ТЗ, MVP)  
**Основная концепция:** съёмная автономная E-paper-панель для интерьера и управления умным домом  
**Платформа:** ESP32-S3, 7,5″ E-paper, сенсорный ввод  
**Статус:** рабочий документ; окончательные электрические и механические параметры требуют проверки

---

## 1. Назначение устройства

**E-Ink Home Art** — устройство, объединяющее два сценария:

1. **Art Mode** — отображение картины, фотографии или графики на электронных чернилах с минимальным энергопотреблением.
2. **Smart Home Mode** — сенсорный интерфейс для отображения и управления устройствами умного дома.

**Главный принцип:** большую часть времени устройство выглядит как интерьерная картина, а не постоянно включённый технический dashboard.

## 2. Пользовательские сценарии

### 2.1. Art Mode

- На экране постоянно остаётся выбранное изображение благодаря бистабильности E-paper.
- При отсутствии взаимодействия микроконтроллер переходит в режим низкого энергопотребления.
- Wi-Fi выключается, когда не требуется обмен данными.
- Изображения хранятся локально; механизм их загрузки и синхронизации уточняется.

### 2.2. Smart Home Mode

- Пользователь касается экрана.
- Микроконтроллер пробуждается, активирует необходимые интерфейсы, при необходимости подключается к Wi-Fi.
- Открывается интерфейс управления умным домом: устройства, комнаты, сценарии, статусы.
- Пользователь выполняет нужное действие.
- После **30–60 секунд бездействия** устройство возвращается в Art Mode и низкопотребляющее состояние.

**Важная инженерная проверка:** возможность пробуждения по GT911 зависит от питания сенсорного контроллера, линии INT и выбранного режима сна ESP32-S3. Схему пробуждения нужно подтвердить отдельно.

## 3. Аппаратная платформа (Revision 1)

| Узел | Выбранное / обсуждавшееся решение | Примечание |
|---|---|---|
| Микроконтроллер | ESP32-S3-WROOM-1-N16R8 | Основной MCU |
| Flash | 16 MB | В составе модуля |

| Дисплей | Good Display GDEY075T7-T01 | Уточнить точное исполнение и совместимость интерфейса |
| Размер дисплея | 7,5″ | E-paper |
| Разрешение | 800 × 480 |  |
| Контроллер дисплея | UC8179 | По ранее рассмотренной документации |
| Интерфейс дисплея | SPI |  |
| Сенсор | GT911 | I²C; поддержка мультитач |
| Беспроводная связь | Wi-Fi 2,4 ГГц | ESP32-S3 |
| Аккумулятор | Li-Po 1S, типоразмер 606090, ориентир ~4000 мА·ч | Ёмкость и размеры проверить по конкретному аккумулятору |
| Зарядное устройство / Power Path | ETA6003Q3Q | Проверить финальную схему |
| Стабилизатор 3,3 В | TPS63802 | Buck-Boost |

| ПО | ESP-IDF, C/C++ |  |

### 3.1. Требования к дисплею

- Поддержка полного обновления изображения.
- Поддержка быстрого/частичного обновления, если это предусмотрено конкретной моделью и её waveform.
- Предотвращение чрезмерного ghosting: периодическое полное обновление по результатам испытаний.
- Экран должен сохранять изображение без постоянного обновления.
- Точное время обновления, число уровней серого и допустимые режимы — **подтвердить по datasheet выбранной ревизии дисплея**.

### 3.2. Требования к сенсорному вводу

- Распознавание касаний в Smart Home Mode.
- Пробуждение устройства касанием, если аппаратная схема и энергобюджет позволяют это реализовать.
- Проверка потребления GT911 в активном и низкопотребляющем режимах.
- Корректная работа при одновременных/быстрых касаниях и после пробуждения.

## 4. Архитектура питания

```text
USB-C 5 V ─────────┐
                    ├── ETA6003Q3Q (заряд + Power Path) ── SYS ── TPS63802 ── 3V3
Li-Po 1S ──────────┘                                             │
                                                                  ├─ ESP32-S3
                                                                  ├─ E-paper / логика
                                                                  └─ Touch / периферия
```

*Схема структурная, не электрическая: точное подключение силовых выводов, защит, конденсаторов и управляющих сигналов должно соответствовать datasheet и итоговой принципиальной схеме.*

### 4.1. Основные требования

1. Зарядка аккумулятора от USB-C.
2. Работа устройства при внешнем питании.
3. Автономная работа от Li-Po.
4. Контроль напряжения / оценки уровня заряда аккумулятора.
5. Защита и корректное поведение при разряде аккумулятора.
6. Минимизация потребления в режиме ожидания.
7. Надёжное питание дисплея во время обновления и ESP32-S3 во время Wi-Fi-передачи.
8. Безопасное переключение между внешним и аккумуляторным питанием.

### 4.2. Параметры, которые ещё необходимо установить

- Пиковый и средний ток при включённом Wi-Fi.
- Энергия одного полного и одного частичного обновления экрана.
- Ток всех узлов в Deep Sleep, включая сенсор и преобразователи питания.
- Реальная полезная ёмкость аккумулятора и целевой срок автономной работы.
- Порог предупреждения о низком заряде и порог отключения.
- Тепловые режимы при зарядке и использовании.

## 5. Программная архитектура

| Подсистема | Назначение |
|---|---|
| `ArtManager` | Выбор, хранение и отображение изображений |
| `DisplayDriver` | Управление UC8179, полным и частичным обновлением |
| `TouchManager` | GT911, обработка касаний и пробуждение |
| `SmartHomeManager` | Абстракция устройств, комнат, статусов и сценариев |
| `YandexProvider` | Интеграция с Яндекс Домом |
| `PowerManager` | Wi-Fi, режимы сна, аккумулятор, тайм-ауты |
| `Settings` | Wi-Fi, авторизация, параметры устройства |

### 5.1. Интеграции

- **MVP:** Яндекс Дом через доступный официальный API и предусмотренный им механизм авторизации (конкретный способ и ограничения API проверить перед реализацией).
- **Следующий этап:** Home Assistant как второй провайдер без переписывания UI и логики состояний.
- **Не входит в Revision 1:** собственный Matter/Thread или Zigbee стек.

### 5.2. Логика состояний

```text
[BOOT]
   │
   ▼
[ART MODE / LOW POWER] ── касание / событие ──► [WAKE]
   ▲                                             │
   │                                             ▼
   │                                      [SMART HOME]
   │                                             │
   └──────── тайм-аут 30–60 с ◄───────────────────┘
```

Логику восстановления подключения, показа статусов и возврата к изображению необходимо проверить на реальном устройстве с учётом скорости обновления E-paper.

## 6. Интерфейс пользователя

### 6.1. Art Mode

- Изображение занимает большую часть полезной площади экрана.
- Нет постоянно отображаемых элементов управления.
- Возвращение к предыдущей картине после завершения работы с интерфейсом.

### 6.2. Smart Home Mode

- Главный экран с группировкой по комнатам и/или устройствам.
- Отображение названия, типа и актуального состояния устройства.
- Базовое управление: включить/выключить, установить доступный параметр, запустить сценарий.
- Интерфейс рассчитан на ограничения по скорости перерисовки E-paper.
- Учитывать русский язык, переносы и кириллические шрифты.

## 7. Конструкция корпуса

**Концепция:** тонкая панель с возможностью настенного крепления и настольного использования.

Требования и направления проектирования:

- Аккумулятор расположен внутри панели.
- Предусмотреть прочное и обслуживаемое крепление дисплея.
- Магнитная док-станция и pogo-контакты для зарядки — рассматриваемая продуктовая функция; конструкция ещё не утверждена.
- USB-C сохраняется как сервисный и резервный интерфейс питания.
- Корпус не должен мешать работе антенны Wi-Fi.
- Необходимы защита дисплея от изгиба и удобный доступ к сборке при ремонте.

**Не зафиксированы:** габариты корпуса, толщина, масса, материал, тепловой режим, схема магнитов и docking-контактов.

## 8. Состав MVP

- [ ] Вывод статического изображения на E-paper.
- [ ] Обработка касаний GT911.
- [ ] Полное и частичное обновление экрана (если поддерживается дисплеем).
- [ ] Переключение Art Mode ↔ Smart Home Mode.
- [ ] Настройка Wi-Fi и авторизация сервиса умного дома.
- [ ] Получение списка устройств и их актуальных состояний.
- [ ] Управление поддерживаемыми устройствами.
- [ ] Возврат в Art Mode по тайм-ауту 30–60 с.
- [ ] Проверка Deep Sleep и пробуждения от сенсора.
- [ ] Работа от аккумулятора и USB-C, зарядка.
- [ ] Измерение и индикация уровня заряда.
- [ ] Тест потребления в основных режимах и оценка автономности.

## 9. Функции следующих ревизий (не блокируют MVP)

- **Reader Mode:** чтение электронных книг на съёмной панели.
- **Home Assistant Provider:** второй интеграционный модуль.
- **Расширенный Art Mode:** расписания, галереи, сценарии показа, синхронизация.
- **Магнитный dock:** если не будет реализован в первой механической ревизии.
- **Другие протоколы:** Matter/Thread/Zigbee рассматриваются отдельно, не входят в MVP.

## 10. Критерии приёмки первого прототипа

Первый прототип можно считать функциональным, если:

1. Он стабильно запускается от USB-C и от аккумулятора.
2. Выводит изображение на весь экран без повреждений и критических артефактов.
3. Принимает касания и переходит в интерфейс умного дома.
4. Подключается к Wi-Fi и позволяет управлять хотя бы одним поддерживаемым устройством.
5. После периода бездействия возвращает Art Mode.
6. Переходит в низкопотребляющее состояние и надёжно пробуждается из него.
7. Корректно отслеживает низкий заряд и не допускает неконтролируемого отключения во время записи данных.
8. Реальное потребление измерено и задокументировано для основных режимов.

**Количественные критерии** (автономность в днях, ток сна в мкА, время реакции интерфейса, точность оценки заряда, допустимое число циклов обновления) пока не согласованы и должны быть добавлены после измерений первой платы.

## 11. Открытые инженерные вопросы

1. Проверить точное соответствие выбранного E-paper, контроллера UC8179 и сенсорного исполнения документации.
2. Подтвердить питание GT911 и работоспособность пробуждения ESP32-S3 через INT.
3. Завершить проверку обвязки ETA6003Q3Q и TPS63802, включая пиковые токи.
4. Выбрать реальный аккумулятор 606090 с подтверждёнными габаритами, защитой и характеристиками.
5. Определить схему измерения уровня заряда.
6. Проверить ограничения и способ авторизации официального API Яндекс Дома.
7. Определить хранение графики и формат конвертации изображений для E-paper.
8. Выбрать политику полного/частичного обновления для ограничения ghosting.
9. Зафиксировать требования к сроку автономной работы и пользовательскому времени отклика.
10. Разработать и испытать механическое крепление/док-станцию.

## 12. Порядок работ

1. **Bring-up hardware:** питание, программирование, базовая диагностика ESP32-S3.
2. **Display + touch:** изображение, SPI, I²C, корректное пробуждение.
3. **Art Mode + power:** локальная графика, режимы сна, измерение токов.
4. **Smart Home MVP:** Wi-Fi, авторизация, получение устройств, команды.
5. **Integration test:** полный сценарий «картина → касание → управление → картина → сон».
6. **Battery + enclosure:** зарядка, автономность, сборка, температурные испытания.
7. **Revision 2:** устранение выявленных проблем и дополнительные режимы.

**Итог:** первоочередная задача Revision 1 — подтвердить работоспособность всей цепочки от питания до перехода между двумя режимами и измерить реальное энергопотребление. Расширенные функции не должны задерживать MVP.
