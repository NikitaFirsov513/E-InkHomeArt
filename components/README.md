# Драйверы E-InkHomeArt

Драйверы подключены к сборке и используются диагностическим приложением
`main/diagnostic_main.c`. Инструкция: [первый запуск](../docs/BRINGUP.md).
Сами компоненты не запускают задачи автоматически и не владеют общей шиной.
Общие SPI/I²C-шины создаёт код запуска платы; драйверы получают
готовые шины и владеют только своими устройствами и буферами.
Вызовы выполняются из задачи, не из ISR. Доступ к одному устройству, включая
его удаление, нужно сериализовать. Callback прерывания должен только уведомлять задачу.

## UC8179 — GDEY075T7-T01

API: `uc8179/include/uc8179.h`.

- `uc8179_new()` — подключение к существующей SPI-шине и выделение внутреннего
  DMA-буфера не более 4096 байт; без сброса панели.
- `uc8179_init()` — явный сброс, настройки полного обновления из OTP и включение
  питания контроллера; также используется для выхода из deep sleep.
- `uc8179_display_frame()` — полный кадр 800×480, строго 48000 байт, 1 бит на пиксель,
  строки подряд, старший бит первым. Передаются родные байты RAM панели без
  инверсии или поворота; буфер приложения может находиться в PSRAM.
- `uc8179_fill()` — полный кадр с повторением заданного байта.
- `uc8179_wait_idle()` — ожидание BUSY: **0 = занят**, 1 = свободен, с конечным тайм-аутом.
- `uc8179_sleep()` — power off и deep sleep. Перед удалением включённой панели
  нужно вызвать сон; `uc8179_delete()` освобождает SPI-устройство и буфер.

Начальные параметры: SPI2, 1 МГц, mode 0, MSB first; CS 47, DC 21, RESET 14,
BUSY 13; рекомендуемый тайм-аут BUSY для первого запуска — 20000 мс.
MOSI 45 и SCLK 48 задаются при создании шины из `board_epd_spi_bus_config`.
После ошибки передачи/обновления требуется повторный `uc8179_init()`.
В этой версии реализовано полное чёрно-белое обновление. Быстрое, частичное
обновление и четыре градации серого пока не реализованы.

Последовательность регистров сверена с normal/full режимом примера
[Good Display T075T7_Arduino_V2.3.5](https://www.good-display.com/companyfile/1838.html).
Сам пример и его изображения в репозиторий не включены.

## GT911 — touch

API: `gt911/include/gt911.h`.

- `gt911_new()` — сброс, выбор адреса через INT/RESET, синхронизация INT и проверка ID `911`.
- `gt911_read()` — до пяти точек: координаты, размер касания и track ID; при отсутствии
  касаний возвращает `ESP_OK` и `count = 0`.
- `gt911_sleep()` / `gt911_wake()` — сон и пробуждение с восстановлением INT как входа.
- `gt911_touch_handle()` — заимствованный handle для подключения GUI/IRQ callback;
  сон/пробуждение следует вызывать через нашу обвязку.
- `gt911_delete()` — освобождение touch и I²C IO; общая шина остаётся доступной LIS2DW12.

Параметры платы: общая I²C0, 100 кГц, RESET 12, INT 9; основной 7-битный адрес
`0x5D`, альтернативный `0x14`. Адрес явно выбирается при сбросе, сканирования нет.
`width`/`height` — нативные размеры координат touch до `swap_xy`/зеркалирования;
если оба равны 0, драйвер читает их из регистров конфигурации контроллера.
`gt911_get_native_resolution()` возвращает эти размеры. I²C-операции имеют
конечный `timeout_ms` (по умолчанию 100 мс).
При первом аппаратном запуске нужно проверить ориентацию сенсора относительно дисплея.
Настройки и калибровка сенсора из его прошивки не перезаписываются.
IRQ callback автоматически не устанавливается; доступен опрос.

Используются официальные компоненты Espressif `esp_lcd_touch_gt911` **1.2.1** и
`esp_lcd_touch` **1.2.1**, Apache-2.0. Версии и хеши зафиксированы в
`../dependencies.lock`, файлы загружаются Component Manager в игнорируемый
`managed_components/`. [Исходный драйвер Espressif](https://github.com/espressif/esp-bsp/tree/master/components/lcd_touch/esp_lcd_touch_gt911).
Обвязка выдерживает минимальные задержки вне зависимости от частоты RTOS tick,
обрабатывает INT при смене адреса/сне и учитывает максимальный индекс координаты
при зеркалировании. Тайминги RESET/INT также сопоставлены с
[реализацией Goodix в Linux](https://github.com/torvalds/linux/blob/master/drivers/input/touchscreen/goodix.c).

## LIS2DW12 — акселерометр

API обвязки: `lis2dw12/include/lis2dw12_idf.h`.

- `lis2dw12_idf_new()` — подключение к общей I²C и проверка WHO_AM_I = `0x44`;
  измерения автоматически не запускаются.
- `lis2dw12_idf_start()` — явный сброс с ограниченным ожиданием, BDU,
  auto-increment, high-performance mode, выбранные диапазон и частота.
- `lis2dw12_idf_read()` — XYZ в raw и mg, с учётом текущего диапазона и режима;
  `ESP_ERR_NOT_FINISHED`, если свежих данных пока нет.
- `lis2dw12_idf_power_down()` — выключение измерений.
- `lis2dw12_idf_context()` — контекст официального register API ST: доступны
  low-power режимы, FIFO, обнаружение движения, ориентация и маршрутизация INT1/INT2.
- `lis2dw12_idf_delete()` — удаление I²C-устройства, общая шина остаётся у вызывающего кода.
  Чтобы остановить измерения перед удалением, нужно явно вызвать `power_down()`.

Параметры платы: адрес **0x19**, 100 кГц, INT1 — GPIO39. Драйвер не устанавливает
обработчик GPIO39: источник прерывания и обработчик выберем в коде запуска.
Обвязка `start()` поддерживает ±2/4/8/16 g и ODR 12,5…1600 Гц в high-performance mode.
Остальные режимы доступны через register API ST.

Официальные `lis2dw12_reg.c/.h` сохранены без изменений в `lis2dw12/vendor/`;
источник и commit указаны в `vendor/UPSTREAM.md`, лицензия BSD-3-Clause —
в `vendor/LICENSE`. [Репозиторий STMicroelectronics](https://github.com/STMicroelectronics/lis2dw12-pid).

## Проверка

Проверяется компиляция с ESP-IDF 6.1 для ESP32-S3 и статическая диагностика.
Работа на реальных устройствах, полярность изображения и ориентация touch
будут проверены диагностическим приложением после сборки платы. В приложении
есть ADC, кнопки и тестовый интерфейс; они не являются частью этих трёх драйверов.
